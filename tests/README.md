\# Тестирование NotificationStub



\## 1. Назначение



Для проверки REST API проекта используется PowerShell-скрипт `requests.ps1`.



Скрипт автоматически отправляет HTTP-запросы к запущенному приложению, выводит запросы и ответы сервера, проверяет результаты операций и показывает итоговое количество пройденных тестов и ошибок.



\## 2. Требования



Перед запуском необходимо:



\- установить .NET SDK, совместимый с проектом;

\- запустить приложение NotificationStub;

\- убедиться, что API доступен по адресу `http://localhost:5292`;

\- использовать Windows PowerShell.



\## 3. Запуск приложения



Откройте первое окно PowerShell, перейдите в корневую папку проекта и запустите приложение:



```powershell

cd "Q:\\Учеба\\Практика№1\\NotificationStub"

dotnet run --urls "http://localhost:5292"

```



Оставьте это окно открытым на время тестирования.



Если приложение уже запущено на другом порту, используйте фактический адрес приложения при запуске тестов.



\## 4. Запуск тестов



Откройте второе окно PowerShell и перейдите в корневую папку проекта:



```powershell

cd "Q:\\Учеба\\Практика№1\\NotificationStub"

```



Разрешите выполнение сценариев только для текущего окна PowerShell:



```powershell

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

```



Запустите тестовый скрипт:



```powershell

.\\tests\\requests.ps1 -BaseUrl "http://localhost:5292"

```



Настройка `ExecutionPolicy` с областью `Process` действует только в текущем процессе PowerShell и не изменяет политику выполнения для всей системы.



Если приложение работает на другом порту, укажите соответствующий адрес в параметре `-BaseUrl`.



\## 5. Какие проверки выполняются



Скрипт выполняет семь групп проверок:



1\. \*\*Доступность API\*\* — отправляет `GET /api/requests` и проверяет, что сервер отвечает.

2\. \*\*Приём уведомлений\*\* — отправляет два тестовых уведомления методом POST: платёж и возврат.

3\. \*\*Сохранение записей\*\* — проверяет, что оба уведомления появились в хранилище.

4\. \*\*Поиск по полю JSON\*\* — ищет запись по условию `field=status\&value=success`.

5\. \*\*Поиск по пути\*\* — ищет уведомление по пути `/notifications/payment`.

6\. \*\*Пагинация\*\* — проверяет получение одной записи при параметрах `offset=0\&limit=1`.

7\. \*\*Очистка хранилища\*\* — вызывает `DELETE /api/requests` и проверяет, что после удаления записей не осталось.



Во время выполнения скрипт выводит HTTP-метод, URL, тело POST-запроса, HTTP-статус ответа, содержимое ответа сервера и результат каждой проверки.



\## 6. Ожидаемый результат



При успешном выполнении всех проверок в конце выводится:



```text

========================================

ИТОГ: пройдено 7, ошибок 0.

========================================

```



Строка `\[PASS]` означает, что соответствующая проверка пройдена. Строка `\[FAIL]` означает, что проверка завершилась ошибкой.



\## 7. Важное замечание



В конце тестирования скрипт очищает хранилище через `DELETE /api/requests`. Это сделано для того, чтобы тестовые записи не оставались в памяти приложения после проверки.



Запускайте тесты на экземпляре приложения, данные которого можно очищать. Если в хранилище находятся нужные данные, предварительно сохраните их.
