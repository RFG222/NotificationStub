
# NotificationStub

Mock-сервис на ASP.NET Core для приёма и просмотра уведомлений.

## Возможности

- Приём JSON-уведомлений по POST-запросам.
- Хранение записей в оперативной памяти.
- Сохранение ID, времени получения, пути запроса и тела уведомления.
- Ограничение количества записей с вытеснением старейших записей по FIFO.
- Поиск по ID, пути, именам JSON-полей и значениям.
- Фильтрация по пути, имени поля и значению.
- Пагинация через offset и limit.
- Полная очистка хранилища.
- Фоновое удаление устаревших записей.
- Логирование и Swagger UI.

## Требования

- .NET SDK 10.0 для локальной сборки.
- Docker и Docker Compose для запуска в контейнере.

## Локальный запуск

Выполните в каталоге проекта:

```powershell
dotnet restore
dotnet build
dotnet run
```

Откройте адрес, который приложение выведет в консоль, и добавьте `/swagger` для просмотра API.

## HTTP API

### Приём уведомления

`POST /notifications/payment`

Тело запроса:

```json
{
  "event": "payment",
  "amount": 1500,
  "status": "success"
}
```

### Получение записей

`GET /api/requests`

Параметры:

- `q` — общий текстовый поиск.
- `path` — фильтр по пути.
- `field` — имя поля JSON.
- `value` — значение поля или общий поиск по значениям.
- `offset` — число пропускаемых записей, по умолчанию 0.
- `limit` — число возвращаемых записей, по умолчанию 50, максимум 1000.

Примеры:

- `/api/requests?q=payment`
- `/api/requests?field=status&value=success`
- `/api/requests?path=payment&offset=0&limit=20`

### Очистка записей

`DELETE /api/requests`

## Конфигурация

Параметры задаются в `appsettings.json` или переменными окружения:

- `MAX_STORAGE_SIZE`: 0 — без ограничения.
- `CLEANUP_INTERVAL_SECONDS`: интервал автоочистки в секундах.
- `RETENTION_PERIOD_SECONDS`: срок хранения в секундах.
- `AUTO_CLEANUP_ENABLED`: включение или отключение автоочистки.

## Запуск через Docker Compose

```powershell
docker compose up --build
```

После запуска приложение будет доступно на порту 8080 хоста.

## Архитектура хранения

Данные хранятся в памяти процесса и теряются при его перезапуске.
Для хранения используются словарь записей и связанный список,
который задаёт порядок поступления. Доступ к обоим объектам
защищён блокировкой, чтобы операции добавления, удаления и
вытеснения выполнялись согласованно.
