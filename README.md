# Сервис-заглушка для приёма уведомлений (Notification Stub Service)

Микросервис на базе **ASP.NET Core (.NET 8)**, предназначенный для временного хранения входящих HTTP-уведомлений в оперативной памяти, управления лимитами с FIFO-вытеснением, выполнения поиска, пагинации и автоматической фоновой очистки устаревших данных.

## 1. Технологический стек

* **Язык программирования**: C# (.NET 8)

* **Веб-фреймворк**: ASP.NET Core Web API

* **Хранение данных**: Встроенные потокобезопасные коллекции .NET (In-Memory)

* **Документация API**: Swagger / OpenAPI

* **Контейнеризация**: Docker, Docker Compose

## 2. Архитектура хранилища и обоснование выбора коллекций

Для безопасной работы в многопоточной среде ASP.NET Core без использования внешних баз данных применяются стандартные коллекционные примитивы из пространства имён `System.Collections.Concurrent`:

1. **`ConcurrentDictionary<Guid, StoredRequest>`**:

   * Используется для основного хранения входящих уведомлений.

   * Обеспечивает мгновенный доступ, добавление и удаление элементов по ключу `GUID` за время $O(1)$.

   * Гарантирует потокобезопасность при параллельной обработке HTTP-запросов.

2. **`ConcurrentQueue<Guid>`**:

   * Хранит последовательность идентификаторов запросов в порядке их поступления.

   * Используется для реализации стратегии **FIFO (First-In, First-Out)**: при превышении допустимого лимита `MAX_STORAGE_SIZE` наистарейший идентификатор извлекается из очереди, после чего связанная запись удаляется из словаря.

## 3. Переменные окружения и конфигурация

Параметры работы сервиса настраиваются через переменные окружения (или в `appsettings.json`):

| Переменная | Описание | Значение по умолчанию | 
| ----- | ----- | ----- | 
| `MAX_STORAGE_SIZE` | Максимальное количество одновременно хранящихся записей (`0` — без ограничений) | `0` | 
| `CLEANUP_INTERVAL_SECONDS` | Интервал запуска фоновой очистки (в секундах) | `600` (10 мин) | 
| `RETENTION_PERIOD_SECONDS` | Время жизни записи в памяти (в секундах) | `3600` (1 час) | 
| `AUTO_CLEANUP_ENABLED` | Включение/отключение фоновой очистки по времени (`true`/`false`) | `true` | 

## 4. Инструкция по сборке и запуску

### Вариант A: Локальный запуск (.NET CLI)

1. Убедитесь, что установлен **.NET 8 SDK**.

2. Перейдите в каталог проекта:

   ```
   cd NotificationStub
   
   ```

3. Запустите проект:

   ```
   dotnet run
   
   ```

4. Откройте в браузере документацию Swagger по адресу: `http://localhost:5292/swagger (может немного отличаться)`

### Вариант B: Запуск через Docker Compose

1. Убедитесь, что запущен **Docker Desktop**.

2. В корневой директории проекта выполните команду:

   ```
   docker compose up --build
   
   ```

3. Сервис станет доступен по адресу:
   `http://localhost:8080` (интерфейс Swagger: `http://localhost:8080/swagger`).

## 5. Примеры cURL-запросов для тестирования

### 1. Приём уведомления (POST)

```
curl -X 'POST' \
  'http://localhost:5292/test' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "message": "Привет, это тестовое уведомление",
  "code": 200
}'

```

### 2. Получение списка сохранённых запросов (GET)

```
# Получение всех записей с пагинацией
curl -X 'GET' 'http://localhost:5292/api/requests?offset=0&limit=50' -H 'accept: application/json'

# Поиск по ключевому слову
curl -X 'GET' 'http://localhost:5292/api/requests?q=тестовое&offset=0&limit=10' -H 'accept: application/json'

```

### 3. Полная очистка хранилища (DELETE)

```
curl -X 'DELETE' 'http://localhost:5292/api/requests' -H 'accept: application/json'

```
